## Issue Types & Fixes

### Missing Required Field

**Problem:** API response is missing a field required by the spec

**Fix Strategy:**
- Add field to response serializer
- Ensure field is populated from data model
- Return appropriate default if data unavailable

```python
# Example fix for Flask
response_data = {
    "id": user.id,
    "email": user.email,     # ← Add missing field
    "name": user.name,
    # ... other fields
}
```

### Type Mismatch

**Problem:** Field has wrong type (e.g., int instead of string)

**Fix Strategy:**
- Convert to correct type in serializer
- Or update OpenAPI spec if current type is correct

```python
# Fix: Convert to spec-expected type
response_data = {
    "user_id": str(user.id),  # Convert int to string if spec expects string
    "age": int(user.age),     # Convert string to int if spec expects int
}
```

### Extra Fields

**Problem:** Response includes fields not in spec

**Fix Strategy:**
- Remove sensitive/internal fields
- Or add to spec if field should be public

```python
# Fix: Use explicit serializer (don't return all fields)
class UserSerializer:
    def serialize(self, user):
        return {
            "id": user.public_id,
            "name": user.name,
            # DON'T include: user.internal_id, user.debug_info
        }
```
